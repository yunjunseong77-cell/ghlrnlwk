훈련병장 회귀자는 전역하고 싶어 — 개발 인수인계
기준: 2026-11-12 / 다른 PC와 새 채팅에서 이어가기

이 문서는 지금 구현된 내용과 앞으로의 의도를 구분한다. 먼저 실제 코드와 화면을 확인한 뒤 이어서 개발한다.
설치와 실행 방법은 루트 README.txt 및 시작 안내.txt, 에이전트 작업 규칙은 AGENTS.md를 함께 읽는다.

1. 사용자가 만들려는 게임

Windows에서 실행하는 Godot 네이티브 게임이다. 웹사이트나 브라우저 게임으로 바꾸지 않는다.
이름은 “훈련병장 회귀자는 전역하고 싶어”. 기본 이름은 윤준성이지만 시작할 때 사용자가 정한다.
말년병장이 전역날 동료들과 작별한 뒤 위병소 밖에서 트럭에 치인다.
기상나팔을 듣고 깨어나니 훈련소 이틀 차 아침. 몸과 두뇌는 병장 시절의 경험을 기억한다.
신분만 훈련병이라 조교에게 병장처럼 대들었다가 상황을 깨닫는다.
주인공에게만 보이는 퀘스트를 깨며 에이스 훈련병·병사로 성장하고 다시 전역하려는 이야기다.

군생활 에피소드와 인물은 사용자의 실제 경험을 바탕으로 한다. 기존 대사와 말투를 임의로 순화하거나 갈아엎지 않는다.
주요 인물: 박환태 중대장, 한상철 행보관, 정석원 소대장, 유명선 부소대장,
전윤탁 하사, 안수민 하사, 병인, 지호, 희성 등. 프롤로그의 확정된 대사는 data/prologue.json이 기준이다.

장기 흐름은 훈련소 → 공병 폭파병 배정에 충격 → 상무대 후반기 교육 → 8사단 배정
→ 전입 대기 장소에서 3~4일 정도 대기 → 8사단 공병대대 생활이다.
전입 대기 장소는 현재 “보충중대”라는 가칭이며 당시 정식 명칭·기간·세부 교육 일정은 미확인이다.
이후 각국의 회귀자, 스킬, 회귀자를 알고 전쟁에 이용하려는 세력이 드러나는 성장형 RPG로 확장한다.
회귀자마다 다른 목적과 퀘스트가 충돌할 수 있다. 주인공의 핵심 목표는 끝까지 전역이다.
초반의 군생활 코미디와 동료 관계를 쌓고 장기 설정을 점차 드러낸다. 초반부터 미래 보직과 세계관을 모두 설명하지 않는다.

2. 사용자가 명확히 정한 품질 방향

단순 시뮬레이션이 아니라 실제 조작과 판단으로 훈련을 깨는 게임이다.
사격, 군장 준비, 행군, 방독면 등의 개별 훈련도 다시 즐길 만큼 재미와 성취감이 있어야 한다.
시점은 탑다운 2D. 탐색, 동료 대화, 퀘스트, 훈련, 보상, PX와 장비 성장이 연결된다.
큰 기능 수보다 조작감·타격감·읽기 쉬운 화면·몰입·반복 플레이의 재미가 중요하다.
테스트 통과만으로 “재미있고 고퀄리티”라고 판단하지 않는다. 실제 실행 화면과 플레이 흐름을 검토한다.

사용자가 14동작 구령 따라 하기 방식의 제식 게임을 매우 재미없다고 거절했다.
현재 제식은 짧은 이야기 사건으로 바뀌었다. 기존 제식 게임을 필수 진행이나 재도전 목록에 되살리지 않는다.
침상 정리는 첫 튜토리얼로 받아들였지만 단순하고 쉬웠다는 평가였다. 이후 훈련의 품질 기준으로 삼지 않는다.
다음 실제 게임으로 사용자가 고른 것은 “조준·명중 타격감과 콤보 중심 사격”이며 현재 구현되어 있다.

모자 판매용 아이콘을 머리에 그대로 붙이는 외형은 사용자가 부자연스럽다고 지적했다.
장비는 방향·보행 프레임·신체 위치·앞뒤 가림에 맞춰 착용해야 한다.
회복 소모품은 향후 전투 등에서 필요할 때 직접 쓰는 HP/SP 아이템이다.
침상이나 사격 시작 시 자동으로 소모되는 임시 버프로 되돌리지 않는다.

3. 현재 실제로 플레이할 수 있는 범위

타이틀: 큰 제목 등장, 총성·탄흔 연출, 깜빡이는 GAME START, 시작 전환.
이름: 최대 12자, Windows 네이티브 입력 대화상자. 한글 IME 덮어쓰기 문제를 피하도록 구현했다.
프롤로그: 전역날 아침 → 행정반 → 위병소 작별 → 경적·사고 → 훈련소 이틀 차 회귀.
퀘스트: 이미지, 목표, 시간, 보상, 장비 효과를 확인하고 수락해야 시작한다.
침상: 모포 두 번·매트리스 한 번을 마우스로 접고 매트리스 → 모포 → 베개 순서로 적재한다.
기본 60초/80점. 접기 45%, 위치 30%, 각도 25%. 휠·Shift+휠·오른쪽 드래그로 회전한다.
탐색: 생활관 앞, 연병장, 식당, PX, 훈련 준비실, 사격장 이동로를 잇는 첫 구역.
이동·충돌·클릭 경로 이동·미니맵·전체 지도·NPC·퀘스트·위치 저장을 구현했다.
현재 지도는 실제 훈련소 배치도 복원이 아니라 분위기를 바탕으로 만든 창작 구역이다.
진행: 침상 통과 → 조교 점검 → 동기 대화 → 짧은 제식 사건 → 며칠 뒤 첫 사격일
→ 동쪽 사격장 이동로의 퀘스트 → 사격 → 점수별 조교 반응 → 동기 대화·PX·자유 탐색.

사격: 45초, 8발 탄창, 팝업 → 이동 → 혼합 표적의 세 단계. 처리하면 즉시 다음 묶음이 나온다.
마우스로 겨눈 위치가 명중 위치다. 무작위 탄퍼짐으로 입력을 배신하지 않는다.
중앙 PERFECT, 최대 5배 콤보, 반동·탄피·명중음·쓰러지는 표적·결과 및 최고 기록을 구현했다.
R 또는 빈 탄창 자동 재장전, 재장전 0.85초. 평가 70점 이상과 18개 이상 명중을 모두 만족해야 통과한다.
평가는 정확도 60%, 명중 수 20%(35개 최대), 중앙 명중 비율 20%. 기본 명중으로도 합격할 수 있다.
타이틀 “사격 바로하기”와 훈련 목록의 바로 도전으로 프롤로그 없이 먼저 플레이할 수 있다.

PX: 장비 8종, 회복 아이템 4종, 이미지·가격·상세 효과·소지 수량·구매.
장비: 머리·손·발·군장·손목·명찰 6부위. 같은 부위는 하나만 착용한다.
모자, 두 종류 장갑, 전투화, 시계, 어깨 패드, 수통, 명찰이 방향과 보행에 맞춰 반영된다.
장비창의 앞·왼쪽·오른쪽·뒤 및 걷기 미리보기는 탐색 캐릭터와 같은 렌더러를 쓴다.
회복: 초코파이 HP 30, 믹스커피 SP 35, 에너지바 HP 20+SP 20, 이온음료 SP 50.
아이템창의 사용하기 또는 퀵슬롯 1·2로 사용한다. 공통 대기시간은 1.5초, 종류별 최대 소지는 99개.
필요한 자원이 가득 찼거나 사용 불가 상태면 수량을 줄이지 않는다. 효과와 수량 차감을 함께 저장한다.
HP/SP 최대 100. 실제 달리기 중 SP 12/초 소모, 1초 쉬고 SP 8/초 회복. 벽을 밀면 소모하지 않는다.
메뉴·퀘스트·미리보기에서는 상태가 바뀌지 않는다. SP 소진 시 걷기로 전환한다.

미구현: 적과 싸우는 실제 전투, 능동 스킬, 이후 훈련, 건물 내부, 상무대·8사단 챕터.
피해·회복 API와 테스트가 있어도 전투 콘텐츠가 완성된 것은 아니다.
독립 배포용 Windows EXE도 아직 별도 내보내기가 필요하다. 게임 실행.cmd는 설치된 Godot을 여는 개발용 실행기다.

4. 중요한 파일

project.godot / scenes/main_menu.tscn: 진입점, 1280×720, canvas_items, GL Compatibility.
scripts/main_menu.gd: 타이틀·닉네임·프롤로그·음원·퀘스트·캠페인·화면 전환.
data/prologue.json: 프롤로그 대사와 장면. [name]은 전체 이름, [given]은 한글 세 글자 이름만 성을 뺀 호칭.
data/training_catalog.json: 훈련·보상·퀘스트·임시 화폐 이름 “훈련 코인”. 미래 훈련 항목은 아직 장면이 없는 계획이다.
data/px_items.json: 장비·소모품·효과·가격·아이콘 번호.
data/camp_world.json: 탐색 구역 배치와 시설.
scripts/training_progress.gd: 계정 데이터·구매·장착·보상·회복·HP/SP·저장.
scripts/training_hub.gd / quest_window.gd: 훈련 목록, PX, 인벤토리, 장비, 퀘스트 UI.
scripts/camp_world.gd / camp_actor.gd / camp_minimap.gd: 탐색과 캐릭터·지도.
scripts/soldier_appearance.gd / equipment_portrait.gd: 공통 착용 외형·장비 미리보기.
scripts/item_art.gd: 판매용 아이콘. 착용 렌더링과 구별한다.
scripts/bedding_game.gd / bedding_piece.gd / scenes/training/bedding.tscn: 침상 게임.
scripts/shooting_game.gd / scenes/training/shooting.tscn: 사격 게임.
scripts/drill_game.gd / scenes/training/drill.tscn: 폐기된 제식 게임의 호환용 코드. 활성 게임이 아니다.
docs/게임 진행안.txt: 캠페인·장기 설정·군 교육 자료와 미확인 사항.
docs/훈련과PX안내.txt: 경제·아이템·훈련 세션 계약과 검증 범위.
assets/audio/음원안내.txt, 출처.txt, 사격효과음출처.txt: 음원 연결과 출처.
docs/asset-prompts.json, assets/art/*/prompts.txt: 이미지 생성 기록.

5. 깨뜨리면 안 되는 저장·진행 규칙

Godot user://에 실제 플레이 기록을 저장한다. Git에 플레이어 저장 파일을 넣지 않는다.
training_profile.cfg: 계정 코인·훈련 기록·장비·수량·퀵슬롯·HP/SP. 현재 스키마 버전 3.
progress.cfg: 이름·대사 위치·설정·캠페인 훈련 완료·탐색 활성 여부.
camp_progress.cfg: 위치·동기 및 조교 대화 진행 상태.
새 이야기는 본편과 탐색 진행을 초기화하지만 계정 코인·보유 물품·재도전 기록은 보존한다.
홈에서 먼저 사격을 완료해도 본편 퀘스트 완료로 간주하지 않는다.
최초 보너스는 계정 기준 한 번만 지급한다. 이전 제식 완료를 사격 완료로 바꾸지 않는다.
미리보기에서는 실제 보상·위치·상태를 변경하지 않는다.
탐색에서 시작한 훈련은 성공·실패·포기와 관계없이 진입했던 탐색 위치로 복귀한다.

훈련 계약: begin_run(id, source) → 실제 시작 직전 activate_run(token)
→ 결과 확정 시 finish_run(token, score, passed, metrics) 또는 cancel_run(token).
준비 화면이나 퀘스트를 여는 것만으로 시간·보상·완료 상태를 변경하지 않는다.
동일 토큰은 중복 정산하지 않는다. 실패·포기는 코인이나 해금을 주지 않는다.
저장이 실패하면 성공으로 표시하거나 캠페인을 완료 처리하지 않는다.
장비 효과는 실제 시작 시 스냅샷으로 확정한다. 회복 아이템은 모든 훈련에서 자동 소모하지 않는다.
ConfigFile 임시 저장 후 이름 변경 방식의 원자적 저장을 유지한다.

이전 prepared 회복 아이템은 수량을 줄이지 않고 퀵슬롯 1로 옮긴다.
use_item(id, "exploration" 또는 "combat"), assign_quick_slot(index, id), use_quick_slot(index, context)가 공통 진입점이다.
apply_damage(amount), get_vitals(), tick_vitals(delta, sprinting), save_vitals()를 사용하고 화면마다 별도 HP를 만들지 않는다.
아이템 사용 실패나 저장 실패 시 효과와 소지 수량이 어긋나지 않아야 한다.

이름 입력은 DisplayServer.dialog_input_text의 Windows 네이티브 EDIT를 사용한다.
조합 중 텍스트를 매 프레임 덮어쓰는 LineEdit 방식으로 되돌리지 않는다. “윤준성”을 실제 한글 입력으로 확인한다.
게임 화면 진입 시 타이틀·대사 UI를 숨기는 처리를 유지한다. 숨겨진 버튼이 사격 클릭을 가로채던 문제를 수정한 부분이다.
경적·당황·충돌 자동 진행은 일시정지 중 멈춰야 한다. 기상나팔은 두 장면 모두 11초 제한을 유지한다.

6. 음원과 아트

사용자 제공 BGM은 assets/audio/에 이미 복사되어 있다. 다른 PC의 Downloads 경로에 의존하지 않는다.
dawns_quiet_call.mp3: 전역날부터 사고 직전. 경적과 함께 정지.
recruit_morning.mp3: 회귀 뒤 대사와 탐색.
ceremonial_charge.mp3: 침상과 사격. 사격 BGM은 효과음을 위해 -15dB, 기본 장면 BGM은 -6dB.
reveille_11s.ogg: 제공된 기상나팔의 앞 11초.
타이틀·사격 총성, 경적, 충돌, 웃음 등은 출처가 기록된 실제 녹음 효과음이다.
shoot_reload.ogg는 주유기 기계 녹음을 활용한 폴리이며 실총 재장전 녹음이라고 설명하지 않는다.
한국어 “충성” 녹음은 현재 없다. 선택적 salute 음원 경로만 준비되어 있다.
원본 캐릭터 시트는 recruit_walk.png이며 앞·왼쪽·오른쪽·뒤 4열 × 서기·걷기A·걷기B 3행이다.
생성된 착용 아트와 판매 아이콘은 각각 프로젝트에 포함되어 있다. 개발자의 .codex/generated_images 경로는 실행에 필요 없다.
폰트·효과음의 라이선스와 출처 파일을 보존한다. 전체 프로젝트에 임의의 오픈소스 라이선스를 부여하지 않는다.

7. 새 PC에서 검증하기

확인된 개발 엔진은 Godot 4.7.2 stable이다. 소스는 UTF-8이다.
PowerShell Get-Content로 한글을 읽을 때는 -Encoding UTF8을 명시한다.
먼저 Godot 에디터에서 project.godot을 열어 자원을 임포트한다. .godot은 생성되는 캐시이며 저장소에 필요 없다.
자동 검증은 Godot 콘솔 실행 파일을 쓴다. 아래 경로의 godot_console은 새 PC에 설치된 콘솔 실행 파일로 바꾼다.

예시 PowerShell:
$godotConsole = 'D:\Tools\Godot\Godot_v4.7.2-stable_win64_console.exe'
& $godotConsole --headless --editor --path . --import
New-Item -ItemType Directory -Force -Path docs/previews | Out-Null
& $godotConsole --headless --path . --script tools/verify_training.gd
& $godotConsole --headless --path . --script tools/verify_vitals.gd
& $godotConsole --path . --script tools/verify_bedding.gd
& $godotConsole --path . --script tools/verify_loadout.gd
& $godotConsole --path . --script tools/verify_camp.gd
& $godotConsole --path . --script tools/verify_shooting.gd
& $godotConsole --path . --script tools/verify_journey.gd
& $godotConsole --path . --script tools/verify_rpg_ui.gd
& $godotConsole --path . --script tools/verify_appearance.gd
& $godotConsole --path . --script tools/verify_native_name.gd

또는 실행기를 사용한다:
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\run_checks.ps1 -Suite all
필요하면 -GodotPath에 설치된 console.exe의 전체 경로를 지정한다.

GUI·마우스·렌더링 검증에는 --headless를 넣지 않는다. 화면 좌표가 필요한 검증은 네이티브 창에서 순차 실행한다.
verify_training: 해금·실패·첫/반복 보상·중복 정산·구매·장비·재실행 보존.
verify_vitals: 이전 저장 이관·수동 회복·가득 찬 자원·대기시간·달리기/회복·저장 실패.
verify_bedding: 마우스 접기·회전·적재·점수·정지·재도전·보상과 BGM 연결.
verify_loadout: 실제 UI 구매·장착·교체·회복·퀵슬롯·장비 효과.
verify_camp: 미리보기 격리·이동/충돌·경로·지도·대화·퀘스트 취소·탐색 복귀.
verify_shooting: 실제 입력·세 단계·정밀 명중·콤보·재장전·정지·실패·보상·재도전.
verify_journey: 타이틀에서 프롤로그와 침상·짧은 제식 사건·사격·후속 대화까지의 연결.
verify_rpg_ui: 회복 UI와 1/2 입력·사방/걷기 미리보기·벽 달리기·정지·저장·미리보기 격리.
verify_appearance: 사방×세 자세 및 각 장비의 렌더링·공통 렌더러.
verify_native_name: 실제 저장과 격리한 네이티브 대화상자 결과·한글 이름 보존·검증·저장. 실제 IME 키 입력은 별도 수동 확인.
verify_drill은 폐기된 제식 코드의 호환 검증용이며 현재 게임의 필수 플레이를 뜻하지 않는다.
검증은 별도 임시 저장 경로를 쓰도록 유지한다. 실제 user://에 테스트 코인·장비·해금을 넣지 않는다.
docs/previews의 생성 이미지를 직접 검토한다. 이전 PC의 통과 기록을 새 PC에서의 검증 결과로 주장하지 않는다.

8. 다음 채팅의 시작점

새 기능을 무작정 늘리기 전에 현재 타이틀, 사격 바로하기, 탐색, PX, 장비창과 회복 흐름을 실행해 본다.
최신 사용자 요청을 우선한다. 다음 실제 전투·각개전투 등 구체적인 제작 대상은 아직 별도로 확정하지 않았다.
RPG로 확장할 때는 기존 HP/SP·수동 회복·장비·저장 계약을 재사용하고, 짧아도 재미있는 플레이 단위부터 완성한다.
현재 구현과 계획을 혼동하지 말고 무엇을 바꿨는지, 어떻게 검증했는지, 무엇이 아직 없는지 분명히 보고한다.
